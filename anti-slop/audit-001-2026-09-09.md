# Anti-Slop Audit 001

**Project:** `gidionsk/laravel-company-portfolio`  
**Date:** 2026-09-09  
**Mode:** AFTER  
**Scope:** public UI, public copy, responsive/accessibility cues, seeded demo content, and code-comment hygiene. Production infrastructure behavior is out of scope except where comments are audited.  
**Basis:** current `main` branch plus the live Railway deployment.

Anti-slop priority mapping used here: Hard Gate = **HIGH**, Purpose-Gate = **MEDIUM**, Quality Lock = **LOW**.

## Findings

1. **HIGH — R-17, R-36, R-38 — Fabricated marketing and dashboard numbers are presented as real evidence.**  
   `resources/views/home.blade.php` renders generated/unsourced values such as `projects shipped`, `94% client retention`, `4.9/5`, `$128.4K`, `42,891`, and `+38.2%`; for a demo portfolio these must be removed or clearly labeled as mock data instead of acting as proof.

2. **HIGH — R-18, R-36, R-38 — Fictional testimonials are presented as real client endorsements.**  
   `database/seeders/DatabaseSeeder.php` seeds realistic names, roles, companies, and quotes (Adrian Raharja, Michelle Tan, Rizky Pratama), while the homepage renders them as genuine testimonials; anti-slop requires verified testimonials or no testimonial section.

3. **HIGH — R-17, R-36, R-38 — Fictional case studies, client identities, and quantitative outcomes are not disclosed as concepts.**  
   Seeded projects such as Nexa Finance, Aruna Living, FlowDesk, and Vanta Commerce include client names and metrics like `+42%`, `2.4x`, `-31%`, and `1.8s`, which makes demo work look like verified commercial work.

4. **HIGH — R-23, R-38 — The hero analytics visual masquerades as a live product artifact.**  
   The `analytics.workspace` window includes a `LIVE` badge, realistic metrics, a chart, and delivery/growth KPIs without an explicit `Concept UI` / `Demo data` label, so a decorative mockup is being disguised as final evidence.

5. **HIGH — R-02 — Em dashes are used throughout interface text and metadata.**  
   Public/admin page titles, SEO fallbacks, settings placeholders, and empty-value fallbacks contain `—`; anti-slop explicitly forbids em dashes in interface copy.

6. **HIGH — R-25 — Several normal-text color combinations fail WCAG AA contrast.**  
   Current CSS includes `#77767b` on `#f8f7f4` (~4.21:1), `#a09ea4` on `#f8f7f4` (~2.48:1), and `#606066` on `#111114` (~3.02:1), all below the 4.5:1 requirement for the small text where they are used.

7. **HIGH — R-32 — Focus visibility is removed without a robust replacement.**  
   Public contact inputs/selects and admin form controls use `outline: 0` / `outline: none`, while the stylesheet has no consistent `:focus-visible` treatment for links, buttons, form controls, filters, and slider controls.

8. **HIGH — R-03 — Some mobile interaction targets are below the required 44px minimum.**  
   The mobile menu button is `42x42`, testimonial previous/next controls are smaller, dots are tiny, and project filter pills are not guaranteed to reach 44px height; these should be resized without relying on invisible accidental hit areas.

9. **HIGH — R-37 — The shipped UI has no explicit design direction document.**  
   The project does not define a `DESIGN.md` / equivalent rationale for its visual identity, dials, layout rhythm, typography, color, or motion, so the current heavily styled output was shipped without the direction anti-slop requires.

10. **MEDIUM — R-01, R-07, R-10, R-13 — Multiple AI-tell visual techniques are stacked without a written purpose.**  
    The UI combines purple/cyan gradients, radial orbs, a grid background, full-page noise, glow, glass blur, and floating shadows across hero/header/cards/contact; each technique is allowed individually, but the cluster has no documented hierarchy or identity reason.

11. **MEDIUM — R-08 — Arrows have become the default decoration for CTAs and cards.**  
    `↗`, `→`, and `↓` appear on the primary CTA, work link, about link, every service card, every project card, case-study links, social links, and submit action, so the arrow is acting as a template signature rather than a specific directional cue.

12. **MEDIUM — R-14 — Capability cards flatten hierarchy instead of reflecting content importance.**  
    All service cards use the same dimensions, padding, spotlight behavior, numeric label, arrow treatment, and tag layout, even though the capabilities have different meanings and do not all need card treatment.

13. **MEDIUM — R-19 — Motion is layered for decoration rather than a declared UX purpose.**  
    The site combines global reveal animation, hero mouse tilt, service-card spotlight, hover lifts, scroll progress, and an auto-advancing testimonial slider; the motion stack is not tied to a declared MOTION dial or task benefit.

14. **MEDIUM — R-06 — Typography patterns are used without a written character/readability reason.**  
    DM Sans + Manrope + Georgia are combined with many tiny, uppercase, wide-tracked labels (`ABOUT THE STUDIO`, `CAPABILITIES`, `PROJECT BRIEF`, etc.) but there is no documented typography rationale.

15. **LOW — R-15, R-20 — Some CTA/copy patterns still read like a generic agency template.**  
    Phrases such as `Explore selected work`, `Start a project`, `real traction`, `Built to look good. Built to work harder.`, and `Designed to convert. Built to scale.` could belong to almost any digital agency and do not explain that this is a Laravel portfolio demo.

16. **LOW — R-05 — The homepage structure follows recognizable AI landing-page patterns.**  
    The current narrative is hero + fake proof/dashboard, bento about, equal capability cards, selected work, process, testimonials, and CTA; the bento/default agency rhythm is content-shaped like a template rather than around the real purpose of this demo.

17. **LOW — R-31 + antislop-code — Production files contain decorative AI-style banner comments.**  
    `Dockerfile` and `docker/entrypoint.sh` repeatedly use `# =====...` separator blocks and numbered section banners; retain only comments that explain non-obvious constraints (for example why Apache must use `mpm_prefork`) and remove decorative narration.

## Proposed direction for the approved fixes

This is a proposal only; nothing in the UI has been changed yet.

- **Purpose:** a transparent Laravel portfolio demo for recruiters/clients, not a fictional agency pretending to have clients.
- **Visual character:** editorial product-studio, restrained, technical, proof-first.
- **Dials:** `ENERGY 2 / RHYTHM 3 / MOTION 1`.
- **Identity motif:** project ledger + implementation notes, with actual stack/capability evidence rather than fake business metrics.
- **Palette:** warm neutral + near-black + one muted accent; remove the second neon accent unless it earns a specific hierarchy role.
- **Content policy:** keep fictional projects only as clearly labeled **Concept case studies**; remove fake testimonials and invented results.
- **Motion policy:** only motion that clarifies state or navigation; no cursor-following spotlight/tilt by default.
- **Code-comment policy:** short sentence-case comments only when they explain a reason, constraint, workaround, or non-obvious behavior.

## Approval gate

Per Anti-Slop Mode AFTER, no UI/code fix should be made until the user approves specific finding numbers. Findings not approved must not be touched.
